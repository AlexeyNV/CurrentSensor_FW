# CurrentSensor GUI v0.1.3

Долговременный сегментированный CSF4 архив: [руководство v0.1.3](GUI_0.1.3.md),
[benchmark на ПК](GUI_0.1.3_BENCHMARK.md).

Диагностика выбросов и происхождение профиля: [руководство v0.1.2](GUI_0.1.2.md),
[тесты и benchmark](GUI_0.1.2_BENCHMARK.md).

Новые возможности сохранения, Freeze, статистики X1–X2 и точная семантика metadata:
[руководство v0.1.1](GUI_0.1.1.md). Результаты текущих тестов:
[benchmark v0.1.1](GUI_0.1.1_BENCHMARK.md). Ниже — базовая работа с прибором и записью.

Настольное приложение для FW 0.4.3: один COM-порт, профили из прибора,
осциллограмма исходного тока, полная RAW-запись и диагностика.
Прошивка, SPI DMA, CSF4 v1 и Flash-калибровка на этом этапе не изменены.

## Запуск Windows

Из корня репозитория, Python 3.12 x64:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m current_sensor
```

Выберите COM-порт или введите его вручную, нажмите «Подключить». PuTTY/CLI должны
освободить этот порт. Подключение читает info, ina, regs, cal show,
acq profile list/show; режим DMA подтверждается перед началом измерений.
«Применить профиль» и «Измерять» используют параметры, возвращённые устройством,
а не локальную таблицу характеристик. POLL оставлен для диагностики.
Новые имена профилей принимаются без изменения GUI, если сохраняется текущая
семантика профиля: continuous shunt, ADCRANGE=0, AVG=1, согласованные rate/period.

```powershell
# Явное подключение, без автоматического старта реального прибора
.\.venv\Scripts\python.exe -m current_sensor --port COM5
# Полностью синтетическое устройство; реальный COM не открывается
.\.venv\Scripts\python.exe -m current_sensor --demo
# DEMO с полной RAW-записью
.\.venv\Scripts\python.exe -m current_sensor --demo --record-dir recordings
# Воспроизведение записанных кадров; исходный файл не изменяется
.\.venv\Scripts\python.exe -m current_sensor --replay recordings\capture_NAME.csf4
```

Профиль replay определяется из заголовков кадров и не переключается. Отрезок
записи может не содержать CONFIG/END или начинаться с ненулевого slot. Это
показывается как неполная проверка сессии, а не выдуманное успешное завершение.
Воспроизведение сохраняет исходные номера кадров, коды, timestamps и CRC.

## Работа с графиком

- «Измерять» / «Остановить» управляют приёмом. «Запись RAW» включается независимо:
  до старта она вооружает recorder, во время измерений начинает новый файл.
  Остановка записи не останавливает измерения.
- RAW — режим по умолчанию. MEDIAN3, MEDIAN5 и RAW + MEDIAN3 влияют только на
  представление; ток в CSV, общие MIN/MAX/AVG/STD, ROI и trigger используют RAW.
  Пересчёт для текущих профилей: `I_mA = VSHUNT_CODE / 16`.
- Фильтры причинные, по последним 3/5 соседним слотам. Timestamp результата —
  конец окна. Это задерживает фронты примерно на 1/2 периода соответственно;
  короткий настоящий импульс фильтр тоже может подавить. Пока окно неполное,
  выдаётся RAW. Через разрыв слотов и новую сессию фильтр не продолжается.
- Time/div задаёт десять делений по X, current/div — восемь по Y. Колесо масштабирует
  X относительно указателя; Shift+колесо — Y; Ctrl+колесо — обе оси. Drag перемещает
  график. Ручной zoom/pan фиксирует отображаемую историю, приём и запись продолжаются.
- Freeze фиксирует снимок; при включённом spool полная история снимка подгружается в фоне.
  Без spool доступна ограниченная live-история. Live возвращает слежение.
  Auto X показывает доступную историю. Обзор снизу позволяет перемещать окно.
  «Открыть эксперимент» принимает GUI JSON, RAW binary или CSV существующего CLI.
- Robust Y оценивает процентили 1–99% (для длинного окна — по ограниченной выборке)
  и не растягивает ось из-за одиночного выброса. Пики остаются в RAW; аномалии
  отмечены красными маркерами, обрезанными границей Y. Нажатие на маркер открывает
  амплитуду выбранного режима RAW/CALIBRATED и ближайшие отсчёты. Auto Y включает
  полный диапазон. Y min/max задаются вручную в Manual.
- Два вертикальных/горизонтальных курсора дают Δt, 1/|Δt| и ΔI. «Область» считает
  RAW MIN/MAX/AVG/RMS в выделенном интервале. Наведение показывает ближайший RAW
  slot, TIM2, время и ток в строке состояния. Верхние текущие значения относятся
  к сессии прибора. X1–X2 автоматически считает RAW MIN/MAX/AVG/RMS/N/GAPS независимо от ROI.

Отображение использует first/min/max/last с **исходными временами экстремумов**,
адаптированное к ширине графика. Линия через пропущенные слоты разрывается.
При увеличении показываются исходные точки. Пик длительностью 1–3 отсчёта остаётся
видимым в соответствующем интервале; несколько событий в одном пикселе могут
сливаться. Высота экстремума сохраняется, но длительность субпиксельного события
не считается восстановленной — её следует исследовать увеличением.

## Trigger

Off / Auto / Normal / Single, уровень RAW в mA, Rising/Falling/Level,
гистерезис, pre/post и holdoff. Rising сначала вооружается ниже level−hysteresis,
Falling — выше level+hysteresis. Level реагирует на значение не ниже порога.
Auto при отсутствии события выдаёт свободную развёртку после max(1 s, pre+post).
Single фиксирует одно событие до повторного Arm. Holdoff начинается после
получения post-части. Разрыв слотов сбрасывает ожидающий trigger и состояние фронта.

Это **программный триггер ПК**, не синхронизация INA229/ALERT. Он изменяет только
показанный фрагмент; приём и recorder продолжаются. Диагностика события содержит
`pre_complete` и `contains_gaps`; отсутствующая предыстория не дополняется нулями.
Окно ограничено live-буфером; в одном принятом пакете при нескольких событиях
для отображения сохраняется последнее завершённое, а все RAW остаются в записи.

## Запись и целостность

Уникальные `capture_UTC_UUID.*`:

| Файл | Содержание |
|---|---|
| `.csv` | slot, tim2_read_us, vshunt_code, sample_period_us, time_s; все принятые RAW |
| `.raw.bin` | packed little-endian u32 slot, u32 TIM2, i32 code, f64 time_s: 20 байт/отсчёт |
| `.csf4` | исходные полные CRC-проверенные кадры, возможен отрезок сессии |
| `.json` | профиль, режим, калибровка, счётчики, ошибки, файлы, итоговая диагностика |

Фильтры, Freeze и zoom не меняют эти данные. Повреждённые CRC-пакеты не превращаются
в достоверные измерения; их потеря отражается счётчиками и разрывами slot.
`time_s` отсчитывается от первого принятого отсчёта с учётом rollover TIM2.
TIM2 — момент получения результата MCU, не точный момент преобразования INA229.
Восстановить число полных оборотов TIM2 при разрыве более 2^32 µs нельзя.

`completed` / `recording_closed` означают завершение записи файлов без ошибки
recorder. **Они не означают, что сессия измерений целостна.** Отдельно:

- `transport`: CRC, формат, sequence gaps, resync, END;
- `health.transport_errors`: нарушения кадров/очереди USB;
- `health.acquisition_losses`: LOST_SAMPLE_SLOTS / ACQ_BUFFER_OVERFLOWS прибора;
- `initial_slot_gaps` и `running_slot_gaps`: наблюдаемые начальные/последующие
  разрывы принятых slot; они могут происходить как в acquisition, так и в transport;
- `period_violations`: отклонение TIM2 между соседними слотами более 5 µs от профиля;
- `measured_anomalies`: |I| выше порога или скачок между соседними слотами;
  отрицательный ток около нуля допустим. Аномалия не означает повреждение USB;
- `session_end_verified`: получен END; `health.session_verified`: также проверены
  CONFIG, итоговые profile/mode/session ID и количество USB_SAMPLES_SENT;
- `session_errors`, SPI_ERRORS, DMA_ERRORS/TIMEOUTS остаются отдельными показателями.

При остановке автоматически читаются stream status, timing, anomaly, regs, cal show.
Во время streaming запрашивается только разрешённый бинарный stream status, раз в секунду.
DMA-поля, которых нет в CSF4 STATS v1, до остановки отображаются как «—».
Финальная диагностика сохраняется в JSON и после закрытия COM.
При отключении USB частичная запись закрывается с причиной и неподтверждённым END.
При заполнении очереди recorder запись останавливается с RECORDER_OVERFLOW и
числом не принятых recorder отсчётов; GUI/приём продолжаются. При отказе диска
показывается DISK_ERROR; на полностью недоступном диске JSON тоже может не записаться.

Live-кольцо: 600000 точек (~16,8 MB), 60 s при 10 kHz. Старые live-точки вытесняются
только из экрана, не из файла. Recorder: отдельный поток, очередь 128 блоков.
COM принадлежит одному worker; текстовые команды вне streaming, без конкурентного чтения.
История открывается через NumPy memmap; CSV импортируется блоками по 65536 строк.
Производный кеш median/history хранится в `%TEMP%/CurrentSensorGUI`; его можно удалить
при закрытом GUI. Исходные файлы эксперимента не изменяются.

## Калибровка и диагностика

Вкладка калибровки применяет offset/gain/enabled **отдельными RAM-командами**.
Показывает активные SOURCE/DIRTY прибора. `cal reset` — заводские значения в RAM,
`cal load` — загрузка сохранённых; `cal save` возможен только после отдельного
подтверждения GUI и при остановленном измерении. Автоматической записи Flash нет.
Файлы и статистика RAW не корректируются калибровкой; коэффициенты сессии входят в JSON.
В v0.1.1 график можно переключить в CALIBRATED по зафиксированным коэффициентам сессии.

«Диагностика» содержит ID, регистры, measure, настройки, итоговые USB/SPI/DMA,
timing/anomaly и журнал команд/ответов. Порог |I| отправляется командой
`stream anomaly set N` (целые mA); порог скачка — проверка ПК, 0 отключает её.
Это диагностические признаки, а не удаление данных и не изменение режима ADC.

## Тесты и benchmark

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tools -p "test_*.py" -v
.\.venv\Scripts\python.exe -m unittest discover -s tests_gui -v
.\.venv\Scripts\python.exe -m pip install -r requirements-benchmark.txt
.\.venv\Scripts\python.exe -m tools.benchmark_gui --output build\gui_benchmark.json
.\.venv\Scripts\python.exe -m tools.benchmark_gui --backend builtin --output build\builtin.json
.\.venv\Scripts\python.exe -m tools.benchmark_gui --backend vispy --output build\vispy.json
```

GUI-тесты используют Qt offscreen и mock serial. Проверяются импульсы 1–3 точки,
границы фильтров, gaps, rollover, RAW-файлы, Freeze/Live/zoom/курсоры, trigger,
ошибки CRC/USB/диска, освобождение COM, новые профили и подтверждение cal save.
Benchmark отдельно сравнивает 100k/600k/3M/10M точек, фильтры при 1/2,5/5/10 kHz,
zoom/pan, память/CPU и живой DEMO с записью. Результаты: [GUI_BENCHMARK.md](GUI_BENCHMARK.md).

## Проверка на плате

1. Закрыть PuTTY/CLI, подключить GUI. Проверить FW, INA ID, фактический профиль.
2. Выбрать FAST/DMA, каталог, включить RAW-запись, «Измерять» на 5, затем 30 и 60 s.
3. Переключить RAW/MEDIAN, Freeze/Live, zoom/pan, курсоры и trigger. Проверить, что
   N и счётчик записи продолжают увеличиваться, интерфейс отвечает.
4. Остановить, проверить END, CONFIG, совпадение ADC/USB/принятых/записанных N,
   mode=DMA, session ID, CRC/sequence, LOST_SAMPLE_SLOTS, переполнения, SPI/DMA,
   интервалы TIM2, stream timing и anomaly. Подозрительные значения рассмотреть
   в исходном RAW, не объявляя их ошибкой CRC.
5. Открыть сохранённый эксперимент; приблизить короткий пик, проверить slot/TIM2,
   CSV и metadata. Повторить для BALANCED/PRECISION/LOW_NOISE.
6. Проверить независимую остановку записи и отключение USB, повторное подключение.
   Убедиться, что частичная запись помечена, а COM доступен после закрытия GUI.
7. Калибровку сначала только прочитать. Проверить отмену окна cal save: команда
   не должна отправляться. Реальные коэффициенты без необходимости не менять.

Аппаратные испытания GUI не выполнены. DEMO и benchmark подтверждают работу
программных путей, но не частоту/отсутствие потерь реального USB и не точность INA229.
