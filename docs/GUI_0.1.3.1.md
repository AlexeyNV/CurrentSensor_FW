# CurrentSensor GUI v0.1.3.1 — время длительной записи

В v0.1.3 строка архива вычисляла `time.monotonic() - started_monotonic`
при каждом обновлении GUI, в том числе после `COMPLETE`, `PARTIAL` и
`DISK_ERROR`. Число продолжало расти после Stop, хотя новые RAW-отсчёты
не поступали. Никаких исходных TIM2 timestamps или CSF4 кадров это не меняло.

## Семантика времени

- **Измерение** (`acquisition_elapsed_us`) — разность последней и первой
  принятых RAW-временных меток сессии в микросекундах. GUI разворачивает
  32-битные метки TIM2 в шкалу сессии до передачи архиватору. Время ожидания
  запуска при заранее выбранном режиме записи сюда не входит. В `finish()`
  длительность фиксируется; дописывание очереди в `FINALIZING` её не меняет.
  Для пустой сессии значение равно 0. При ошибке записи в manifest отдельно
  указаны `accepted_first_time_us` / `accepted_last_time_us` и границы
  фактически записанных RAW (`first_sample_time_us` / `last_sample_time_us`).
- **Архивирование** (`recording_wall_elapsed_s`) — монотонное время от создания
  writer при старте записи до завершения его работы. Пока writer активен,
  число растёт; в конечных состояниях оно сохраняется неизменным.
- **Закрытие** (`finalization_duration_s`) — время от перехода в `FINALIZING`
  до завершения writer. При ошибке до `FINALIZING` поле равно `null`.

`session.json` сохраняет `started_utc` (начало записи), `finished_utc`
(вызов `finish()` после завершения acquisition либо остановки записи),
`finalized_utc` (завершение writer) и перечисленные длительности. UTC
показывает календарное время события; длительности не вычисляются вычитанием
календарных часов. После аварии, если момент завершения неизвестен,
`finished_utc` остаётся `null`, а `recovered_utc` указывает только время
восстановления индекса. Оно не подменяет время остановки измерений.

При открытии архива v0.1.3 без новых полей длительность выводится из первого
и последнего индексированных RAW-отсчётов. Время работы архиватора для
старого архива неизвестно и не восстанавливается по времени открытия файла.
При восстановлении повреждённого/отсутствующего индекса длительность
пересчитывается только по проверенным исходным кадрам. Если между
доступными сегментами есть разрыв, сохраняется флаг
`time_continuity_uncertain`. Переполнение TIM2 корректно разворачивается,
пока между соседними полученными метками прошло меньше полного цикла TIM2.

Статус, например:

```text
Архив PARTIAL | измерение 1.628 с | N 16,280 | 0.1 MiB | сегмент 1 | CRC 0 | slots 1 | архивирование 66.6 с | закрытие 0.1 с
```

`PARTIAL` из-за одного стартового слота этим исправлением не меняется.
Freeze, курсоры, история и переключение вкладок не изменяют сохранённое
время. Открытие старого архива не меняет CSF4 и формат его измерений.

## Проверка

```powershell
$env:QT_QPA_PLATFORM='offscreen'
.\.venv\Scripts\python.exe -m unittest discover -s tests_gui
.\.venv\Scripts\python.exe -m unittest discover -s tools
```

На плате: включить «Длительная запись CSF4», начать измерение, остановить
через несколько секунд и сравнить строку архива сразу после Stop и спустя
30 секунд. `измерение`, `N`, `slots` и конечное `архивирование` должны
остаться неизменными. Затем открыть `session.json` через GUI, повторить
сравнение после Freeze/Live и проверить файл инструментом
`python -m tools.verify_archive_013 <путь-к-session.json>`.

Аппаратные испытания именно этого исправления пока не проводились.
